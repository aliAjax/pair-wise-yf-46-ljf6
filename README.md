# pair-wise-yf-46 国际新闻直播编排与突发插播控制台

面向导播、主编、字幕和演播室岗位的直播串联单，维护新闻片、连线、嘉宾、口播和广告；支持时长重算、硬时间风险、突发插播、角色权限、逐条操作历史、单条撤回和断网应急队列。

## 技术栈

React19、TypeScript、Vite、Ant Design、Redux Toolkit、React Router、React Hook Form、Zod、i18next、date-fns、dnd-kit。

## 本地运行

```bash
npm install
npm run dev
npm run build
npm run verify   # 引擎 + thunk 两套规则测试（71 项断言）
```

## 撤回与并发的核心规则

- **逐条留痕**：每次保存按“岗位 / 窗口 / 对象 / 字段前后值 / 对象版本号”记录；同一次编辑改多个字段时拆成多条，可分别撤回。
- **撤回只抵消选中的一次**：执行该条的字段级逆操作（或删除本次新增/插播条目、按相邻锚点还原排序），不再用整张旧快照覆盖当前串联单。
- **播出事实封存**：点“播出”时把计划时长作为**实际时长**写入只追加的「播出记录」(as-run)，条目状态、实际时长、播出记录永远不被撤回改动；已播出条目也不允许再编辑或改时长。播出前的旧改动若随后条目已播出，撤回会被“播出封存”挡住并说明。
- **改动即重算**：累计时间线、计划总时长、硬时间风险全部从当前数据派生（已播出按实际时长推进、跳过不占时长），任何改动或撤回后立即重算。
- **撤回拦截**：撤旧版前检查之后是否有同对象、同字段（或同条目新增/排序等）的改动挡住；挡得住时说明是谁（岗位/窗口）在什么时间又做了什么，需先撤那次。不同字段的后续改动不挡。
- **多窗口并发**：localStorage 作为服务端权威文档，每个条目带 `rev`。提交时做版本条件检查——**先保存者为准**，后保存一方收到冲突提示（说明谁抢先、版本从几到几）、本次不写入，刷新后基于最新版本再改。
- **离线应急**：断网期间本地立即生效并入队；主链路恢复后按顺序重放，逐条做版本检查，冲突条目不覆盖先保存版本并给出提示。本地队列未清空时，外部窗口的推送不会冲掉本地未提交视图。
